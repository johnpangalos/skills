# Feature Flow: fd

## Kind

CLI (existing Rust codebase, clap derive for argument parsing).

## Checks

- Full: `cargo test`; `cargo clippy --all-targets --all-features -- -D warnings`; `cargo fmt -- --check`
- Targeted: `cargo test --test tests <name_substring>`
- Run it: `cargo build && ./target/debug/fd <args>`

## Conventions

- New flag: `src/cli.rs` (clap attrs, `hide_short_help`, `long_help`, conflicts declared in clap), wire through `src/config.rs` / `src/main.rs`; man page `doc/fd.1`; zsh completion `contrib/completion/_fd` (hand-written; bash/fish/ps1 are generated by clap); CHANGELOG.md under `# Upcoming Release` → `## Features` as `- Add \`--flag\` option to ...`; tests in `tests/tests.rs` using `TestEnv` helpers (`assert_output`, `assert_error`, `assert_failure_with_error`).
- `assert_output` trims whitespace and newlines; use `assert_output_raw` when exact bytes matter.
- Output-mode flags live in the receiver in `src/walk.rs` (see `--quiet`).

## Standing criteria

- Every error exits non-zero with a message on stderr (clap usage errors exit 2).
- The existing test suite still passes; a new public feature follows the Conventions above.

## Reviewer checklist

- Exit codes and stderr for every error; conflicting-flag combinations are rejected by clap, not silently ignored.
- Output that fails to write (closed stdout / broken pipe) and Ctrl-C mid-run.
- The change follows the patterns around it (naming, registration, man page, zsh completion, changelog); anything the sibling named in FILES does that the new code should and doesn't is a finding.
