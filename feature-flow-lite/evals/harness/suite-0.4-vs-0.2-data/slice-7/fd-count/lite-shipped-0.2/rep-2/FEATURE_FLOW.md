# Feature Flow: fd

## Kind

Existing codebase of a CLI; Rust, clap derive (`src/cli.rs`).

## Checks

- Full: `cargo fmt -- --check`; `cargo clippy --all-targets --all-features -- -Dwarnings`; `cargo test --locked`
- Targeted: `cargo test --test tests <name_substring>`
- Run it: `cargo build && ./target/debug/fd <args>` (in a temp dir)

## Conventions

- New flag: `src/cli.rs` (clap attrs incl. `conflicts_with`, `hide_short_help`, `long_help`), wiring through `src/config.rs` / `src/main.rs`, man page `doc/fd.1`, zsh completion `contrib/completion/_fd` (hand-written; other shells are generated by clap), CHANGELOG.md under `# Upcoming Release` → `## Features`, tests in `tests/tests.rs` using `TestEnv`.

## Standing criteria

- Existing test suite still passes; every invalid combination is a clap usage error (exit 2, message on stderr).

## Reviewer checklist

- Exit codes and stderr for every error; output that fails to write (e.g. closed pipe).
- `-x`/`-X` swallow every following argument up to `;`, so `fd -x cmd --flag` never triggers a clap conflict; test conflicts with `--exec=cmd` or `-x cmd \;`, and don't count the swallowed form as a finding.
- The new flag appears everywhere its sibling flag does (cli.rs conflicts, man page, zsh completion, CHANGELOG); anything the sibling does that the new code should and doesn't is a finding.
