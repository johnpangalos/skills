ACCEPTANCE CRITERIA:
1. With shadowDOM() on, everything outside the targets is aria-hidden (or inert when shouldUseInert), including siblings of the target inside the target's shadow root and siblings inside every shadow root enclosing it (nested hosts, 2+ levels). Hosts on the path from document root to a target are NOT hidden. Light-DOM siblings of those hosts are hidden as before.
   Hostile: target nested 2 shadow levels deep; target is a direct child of the shadow root (parentElement null); target is itself a shadow host (its own shadow contents must stay visible/untouched); the same element passed twice in targets.
2. Content added after the call anywhere in a target's shadow root or any enclosing shadow root (direct child of the ShadowRoot, or deeper inside a non-target element) gets hidden; content added inside a target stays visible; content added inside an already hidden node does not get its own aria-hidden (no double counting). Elements with data-live-announcer="true" or data-react-aria-top-layer="true" stay visible, both pre-existing in a shadow root and added later into one.
   Hostile: element added directly to a ShadowRoot (mutation target is the ShadowRoot, not an Element); element added inside a hidden sibling; a top-layer element added to a shadow root.
3. Targets may live in different shadow roots (e.g. input in shadow root A, popover in shadow root B, both hosts in body): both hosts stay visible, siblings in each root are hidden, and additions to either root are hidden.
4. The returned function restores every element hidden in light and shadow DOM (aria-hidden removed / inert false, ref counts back to zero) and stops observing all roots: content added afterwards to any of those shadow roots is not hidden. Stacked calls: when an inner call is cleaned up, the outer call's observer resumes observing its shadow roots too (additions to them get hidden again). Calling with shouldUseInert works the same in shadow roots.
   Hostile: nested ariaHideOutside (outer then inner, cleanup inner, add node to shadow root → hidden; cleanup outer → all restored); element pre-hidden with aria-hidden="true" by the page in a shadow root stays hidden after cleanup.
5. `root` option still bounds the hiding: nothing above `root` is hidden (including when root is itself inside a shadow root, or a shadow host whose shadow contains the target).
6. With shadowDOM() off, behavior is unchanged: a target inside a shadow root does not cause its shadow siblings to be hidden or shadow roots to be observed; all existing tests pass unchanged.
7. Tests for all of the above live in packages/@react-aria/overlays/test/ariaHideOutside.test.js; `yarn jest packages/@react-aria/overlays`, `yarn eslint packages/@react-aria/overlays`, `yarn check-types` (2 pre-existing errors in node_modules/@mdx-js are expected), `node scripts/lint-packages.js` and `yarn constraints` pass.
8. `@react-stately/flags` is declared in @react-aria/overlays/package.json dependencies.
