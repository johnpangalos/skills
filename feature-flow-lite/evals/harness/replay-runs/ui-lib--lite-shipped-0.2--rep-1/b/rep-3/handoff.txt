Tabs
- Uncontrolled with `defaultValue`; controlled with `value` + `onValueChange(value: string)`. When controlled and the parent doesn't update `value`, selection does not change (onValueChange still fires). With neither value nor defaultValue, the first non-disabled tab is selected.
- TabList renders role="tablist" with the given aria-label (aria-orientation horizontal is fine). Tab renders a <button type="button" role="tab"> with id, aria-selected, aria-controls=its panel id, tabIndex 0 only for the selected tab and -1 for all others; disabled tabs get `disabled` (or aria-disabled) and cannot be selected by click or keyboard.
- TabPanel renders role="tabpanel", id, aria-labelledby=its tab id, tabIndex 0; only the selected panel is shown (others not rendered or `hidden`).
- Keyboard on a focused tab: ArrowRight/ArrowLeft move focus to next/previous enabled tab, wrapping at the ends and skipping disabled; Home/End go to first/last enabled tab; moving focus selects the tab (calls onValueChange). Clicking an enabled tab selects it. Keys are preventDefault-ed.
  Hostile: first and/or last tab disabled (wrap and Home/End must land on an enabled one); all tabs but one disabled (arrows stay put, no crash); a selected value that matches no tab (still exactly one tab — first enabled — must be tabbable, so the tablist is reachable by Tab); tabs added/removed dynamically after mount keep correct order (order = DOM order, not registration order).

Dialog
- Props: open: boolean, onOpenChange(open: boolean), title: ReactNode, description?: ReactNode, children. Fully controlled; when open=false nothing is rendered.
- Rendered via createPortal into document.body: a backdrop element plus an element with role="dialog", aria-modal="true", aria-labelledby → the rendered title element's id, aria-describedby → the description element's id only when a description is given (attribute absent otherwise).
- On open, focus moves to the first focusable element inside the dialog, or the dialog container itself (tabIndex -1) if there is none.
- Tab from the last focusable element wraps to the first; Shift+Tab from the first (or from the container) wraps to the last; with no focusables, focus stays on the container.
- Escape calls onOpenChange(false). A mousedown+click on the backdrop (outside the dialog content) calls onOpenChange(false); clicks inside the dialog content do not.
- When the dialog closes (open → false, or unmount while open), focus returns to the element that was focused before it opened.
  Hostile: Escape pressed in a nested input inside the dialog still closes; focusable set changes while open (element added) and trap still covers it; disabled buttons / tabindex=-1 / hidden elements are skipped by the trap; the element that had focus was removed from the DOM before close (no throw); onOpenChange must not be called on mount or with true.

Combobox
- Props: label: string, options: {value: string; label: string; disabled?: boolean}[] (export ComboboxOption), value: string | null, onChange(value: string | null), placeholder?. Controlled by value/onChange (the input text shows the selected option's label when not editing).
- Renders a <label> associated with an <input role="combobox"> having aria-expanded, aria-controls → listbox id, aria-autocomplete="list", aria-activedescendant → active option id only when an option is active (absent otherwise). Popup is role="listbox" (labelled by the label) with role="option" children having ids, aria-selected (true for the current value), aria-disabled for disabled options.
- Typing opens the listbox and filters options whose label contains the typed text, case-insensitively (empty text shows all). When no option matches, a "No results" message is shown (not as a role="option") and aria-activedescendant is absent.
- ArrowDown opens the listbox if closed; ArrowDown/ArrowUp move the active option, skipping disabled options (wrap or clamp — document which). Enter on an active option calls onChange(option.value), closes the listbox and sets the input text to that label; Enter with no active option does nothing harmful (no onChange). Clicking an enabled option selects it the same way; clicking a disabled option does nothing. Escape closes the listbox without calling onChange and restores the input text to the selected option's label.
- Blur/clicking outside closes the listbox. When `value` changes from the parent, the input text updates to the new option's label (or empty for null).
  Hostile: all options disabled (Arrow keys leave no active option, Enter does nothing); filter text with regex special chars like "(" or "." or "*" (must be plain substring match, no throw); filter changes after an option was active (active resets to a still-visible enabled option or none — never points at a removed id); clearing the input text to empty calls onChange(null) once (only if value was non-null) — document it; value not matching any option (input shows empty, no crash); options with duplicate labels select by value.

Extra probes worth trying: Tab values containing spaces/special chars/unicode (ids must be valid and unique; aria-controls resolves); Dialog nested inside a Dialog (Escape closes only the top one?) — report as minor; Dialog reopened twice in a row returns focus correctly; React StrictMode double-effects for Dialog focus return and Tabs; Combobox options prop changing while open.

TRIGGERED CHECKS:
## Invariants, round trips and equivalence

- **Trigger:** the criteria state something that must always hold (a balance never negative,
  a total never over a cap), a round trip (parse then format, encode then decode), idempotency
  (doing it twice equals doing it once), or that new code must match old code.
- **Check:** a property test. Use the repo's property library if it has one (Hypothesis,
  fast-check, proptest); otherwise a seeded random loop of at least 1000 generated inputs,
  including the hostile ones, that asserts the property and prints the first failing input.
- **From:** edge cases that the implementor's own tests missed because the tests shared the
  code's assumptions.

## Nesting and composition

- **Trigger:** the code walks a tree or a container (DOM, shadow roots, portals, slots,
  routers, nested config), or the thing it builds can contain another of itself.
- **Check:** nest it. Put a target inside another target, including inside another target's
  shadow root; a dialog in a dialog; a router mounted in a router. Check the inner and the
  outer each still behave as they do alone, and that nothing inside a target gets the
  treatment meant for what's outside it.
- **From:** hide-everything-else logic that walked into a nested target's shadow root, and
  dialogs where one Escape closed both.

## Focus and keyboard

- **Trigger:** the change moves, traps or restores focus, or handles keys (modals, menus,
  tabs, comboboxes, roving tab index).
- **Check:** drive the real component with user events, not function calls. Open it from a
  button and close it: focus goes back to that button, even when a child uses autoFocus. With
  a trap open, Tab and Shift+Tab never reach hidden, inert, disabled or `tabIndex=-1` content,
  including the component's own hidden panels. Escape closes only the top layer. Elements
  added after it opened are handled.
- **From:** focus traps that leaked into hidden content, and focus returned to the wrong
  element.

## Active and selected items in a changing list

- **Trigger:** the component tracks an active, highlighted or selected item in a list that
  can change while it's shown (filtered, async, reordered, prepended).
- **Check:** change the list while it's open: prepend an item, filter, remove the active one.
  The active item must still be the same item, not the same index, and Enter must commit that
  item. Clearing the selection must work (null or empty), and say so in the change event.
- **From:** comboboxes that tracked the active option by index and committed the wrong one.
