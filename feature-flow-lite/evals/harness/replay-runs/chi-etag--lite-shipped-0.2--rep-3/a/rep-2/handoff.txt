2. Methods other than GET and HEAD: `next` is called with the original `http.ResponseWriter` unchanged (no wrapping); status, headers and body are untouched; If-None-Match is ignored.
   Hostile: POST/PUT with a matching If-None-Match must NOT get 304; lowercase method "get" is not GET (net/http methods are case-sensitive).
3. GET/HEAD with a final status of 200 (explicit WriteHeader(200), or implicit via Write, or the handler writing nothing at all) and no `ETag` header set by the handler: the response gets a strong ETag `"<opaque>"` (double-quoted, no `W/` prefix, only etagc characters) that is a deterministic hash of the full buffered body (e.g. hex of sha256 or similar). Same body => same ETag; different body => different ETag. The body sent is byte-identical to what the handler wrote, across multiple Write calls.
   Hostile: body written in many small chunks must hash identically to one big write; empty body (200, no Write) still gets a valid ETag; a handler that sets `ETag` must keep its value exactly (including weak `W/"x"`), never overwritten.
4. HEAD: if the handler wrote no body bytes on HEAD, do NOT invent an ETag from the empty body (it would disagree with the GET ETag); a handler-set ETag is still used for If-None-Match matching. If a HEAD handler does write the body (e.g. via chi's GetHead or a GET handler serving HEAD), the ETag is computed from those bytes and equals the GET ETag for the same content.
5. If-None-Match evaluation (GET/HEAD, final status 200 only), per RFC 9110 §13.1.2 using weak comparison: it matches if the header is `*`, or any listed entity-tag weakly matches the response's ETag (computed or handler-set). Weak comparison: opaque-tags equal, ignoring `W/` on either side (`W/"x"` matches `"x"`, `"x"` matches `W/"x"`). Lists are comma-separated with optional whitespace (OWS), may contain empty members, and multiple If-None-Match header lines are combined (use `r.Header.Values`).
   Hostile: an entity-tag containing a comma inside quotes (`"a,b"` — comma is a legal etagc) is ONE tag and must match ETag `"a,b"` and must not match `"a"`; malformed members (unquoted `abc`, unterminated `"abc`, `W/abc`, `w/"x"` lowercase) must never produce a match, and a valid tag later in the same list should still match; case differs (`"ABC"` vs `"abc"`) => no match; empty header or header of only commas/spaces => no match; `"x"` must not match ETag `"xy"` (no prefix matching).
6. On match: respond `304 Not Modified` with no body, keep the handler's headers (ETag, Cache-Control, Vary, Expires, Content-Location, Date …) and set the ETag header, and delete `Content-Length` (and the body). On no match: respond 200 with the full body and the ETag.
7. Non-200 final status (e.g. 201, 204, 206, 301, 404, 500) on GET/HEAD: passes through unchanged — same status, headers and body, no ETag added, no 304 even if If-None-Match matches a handler-set ETag. Once a non-200 status is written, later writes go straight to the underlying writer (no buffering needed).
   Hostile: `WriteHeader` called twice (200 then 500, or 404 then 200) — the first call wins, as with net/http; a 1xx informational WriteHeader (e.g. 103 Early Hints) is forwarded immediately and is not treated as the final status.
