ACCEPTANCE CRITERIA:
- With enableShadowDOM() on, for a target inside a shadow root, every element outside the targets is hidden: siblings of the target inside its shadow root, siblings inside every enclosing shadow root (nested hosts), and light DOM siblings of the outermost host. Each shadow host on the path to a target stays visible (no aria-hidden, no inert), and the target and its descendants stay visible.
- Same with `shouldUseInert: true`: hidden elements get `inert`, hosts on the path and targets do not.
- After ariaHideOutside runs, an element appended anywhere in a target's shadow root, or in any shadow root enclosing a target, or in the light DOM, gets hidden (await waitFor). An element appended inside a target stays visible. An element appended inside an already-hidden container gets no aria-hidden of its own (same as the light DOM rule).
- Live announcers (`data-live-announcer="true"`) and top-layer elements (`data-react-aria-top-layer="true"`) stay visible both when present before ariaHideOutside runs and when added afterwards inside a target's shadow root or enclosing shadow root.
- Targets in different shadow roots work: e.g. an input in shadow root A and its popover in shadow root B (sibling hosts in body): both targets and both hosts stay visible; everything else in A, in B, and in the body is hidden; content added later in A or B is hidden.
- The returned function restores every element it hid (aria-hidden / inert removed, elements that already had aria-hidden="true" before keep it) and stops observing all roots: content appended to any of those shadow roots after revert stays visible.
- Nested calls (observerStack) keep working with shadow roots: a second ariaHideOutside call disconnects the first's observers on all its roots; reverting the second re-observes the first's roots (content added then in a shadow root is hidden again by the first).
- With shadow DOM support off, nothing changes: all existing ariaHideOutside tests pass unchanged, and a test (run before the flag is enabled) shows that with the flag off, siblings inside a target's shadow root are NOT hidden (documents current behavior).
- `keepVisible` still works for an element inside a shadow root (e.g. added later as a sibling in the shadow root after keepVisible was called, it isn't hidden).
- Existing repo checks pass: `yarn jest packages/@react-aria/overlays`, `yarn eslint` on changed files, `yarn check-types`.
