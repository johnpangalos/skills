Tabs
- T1. `<Tabs>` works uncontrolled (`defaultValue`) and controlled (`value` + `onValueChange`). With no defaultValue/value, the first non-disabled tab is selected. In controlled mode, a parent that ignores onValueChange keeps the old tab selected. onValueChange fires with the new value only when the selection actually changes (not when re-selecting the current tab).
- T2. Roles/ARIA: TabList is role="tablist" with the given aria-label (and aria-orientation="horizontal" is fine); each Tab is a `<button type="button" role="tab">` with aria-selected true/false, aria-controls = its panel's id, and id referenced by its panel's aria-labelledby; disabled tabs have aria-disabled="true" or disabled and cannot be selected by click or keyboard. TabPanel is role="tabpanel", tabIndex=0, aria-labelledby its tab; only the selected panel is shown (others are not rendered or have `hidden`). Ids must be valid even when tab values contain spaces or special characters (e.g. value "a b" or "x/y") — derive ids from useId plus an index or sanitized value, and ids must be unique across two Tabs instances on one page using the same values.
- T3. Only the selected tab has tabIndex=0; all other tabs have tabIndex=-1. Tab key from outside lands on the selected tab; Tab from the selected tab moves to the panel.
- T4. ArrowRight/ArrowLeft move focus to the next/previous enabled tab, wrapping at the ends and skipping disabled tabs; Home/End move to the first/last enabled tab. Selection follows focus (the focused tab becomes selected, onValueChange called). Other keys do nothing and arrow keys call preventDefault.
- T5. Hostile: all tabs disabled except one (arrows keep focus on it, no crash); first and last tabs disabled (Home/End land on the first/last ENABLED tab, wrapping skips them); defaultValue that matches no tab (falls back to first enabled tab, or at least no crash and some tab is focusable); tabs added/removed after mount (keyboard order follows DOM order of the current tabs).

Dialog
- D1. `<Dialog open onOpenChange title description? >children</Dialog>`: when open is false nothing is rendered; when true it renders via createPortal into document.body a backdrop element and an element with role="dialog", aria-modal="true", aria-labelledby pointing to a rendered heading containing `title`, and aria-describedby pointing to an element containing `description` only when description is given (no aria-describedby attribute otherwise). Also accept `className` for the dialog element.
- D2. On open, focus moves inside the dialog: to the first focusable element in it, or to the dialog element itself (tabIndex=-1) if it has none.
- D3. Focus trap: Tab from the last focusable wraps to the first, Shift+Tab from the first wraps to the last; with no focusable children, Tab keeps focus on the dialog. Focusable query must skip disabled elements, tabindex="-1", and hidden inputs.
- D4. Escape calls onOpenChange(false). A mousedown+click on the backdrop (outside the dialog content) calls onOpenChange(false); a click inside the dialog content does NOT. A click that starts inside the content and ends on the backdrop (e.g. drag-select) should not close — track pointerdown/mousedown target.
- D5. When the dialog closes (open goes false, or it unmounts), focus returns to the element that was focused before it opened, if it is still in the document.
- D6. Hostile: Escape inside a Combobox inside the Dialog — if the combobox popup is open, its Escape handling should stop propagation so only the popup closes (Combobox calls stopPropagation/preventDefault on Escape when it was open; Dialog ignores already-defaultPrevented Escape events). Opening with `open` initially true at mount also moves focus in and later restores. onOpenChange not called when the parent keeps open=true (controlled) — dialog just stays open.

Combobox
- C1. `<Combobox label options value onChange placeholder?>`; options: `{ value: string; label: string; disabled?: boolean }`; value is `string | null`; onChange(value: string | null). Controlled by `value`. Also support uncontrolled: if `value` prop is undefined, use `defaultValue?: string | null` internal state. Document this in README.
- C2. Markup: a visible `<label>` associated with an `<input role="combobox">` (getByRole('combobox', {name: label}) works), aria-autocomplete="list", aria-expanded true/false, aria-controls = the listbox id; popup is `role="listbox"` (with aria-label or aria-labelledby the label); options are role="option" with unique valid ids, aria-selected true for the selected value, aria-disabled="true" for disabled ones. placeholder is passed to the input.
- C3. The input shows the selected option's label when closed. Typing opens the listbox and filters options whose label contains the typed text case-insensitively (e.g. "AP" matches "Apple" and "Grape"). Clearing the text shows all options.
- C4. ArrowDown opens the popup if closed; when open, ArrowDown/ArrowUp move the active option (aria-activedescendant on the input = active option id, active option gets a data-active or similar marker attr is optional), skipping disabled options, wrapping at ends (document whichever: wrap). DOM focus stays on the input. When the list is filtered, the active option resets to the first enabled match (or none).
- C5. Enter on an active option calls onChange(option.value), closes the popup, and sets the input text to that label. Enter with no active option does nothing (and doesn't submit a surrounding form if popup is open — preventDefault when open). Clicking an enabled option selects it the same way (use onMouseDown preventDefault so input keeps focus); clicking a disabled option does nothing.
- C6. Escape closes the popup without calling onChange and restores the input text to the selected option's label (or empty if none); aria-expanded becomes false and aria-activedescendant is removed.
- C7. When nothing matches, the popup shows a "No results" message (e.g. a `<div role="status">` or an option-less listbox sibling with text "No results"); no role="option" elements rendered; Enter does nothing.
- C8. Blur (focus leaving the input) closes the popup and restores the text to the selected label.
- C9. Hostile: all options disabled (ArrowDown sets no active option, no infinite loop); empty options array (shows "No results" when opened); option values with spaces/special chars produce valid unique ids; typed text with regex characters like "(" or "." or "[" must not throw (use string includes, not RegExp); a value prop that matches no option shows empty input; the controlled value changing externally updates the displayed text; label text with different case/whitespace still matches by includes on lowercase.

Extra probes worth running: two Dialogs nested/stacked (Escape closes only the top one); Dialog opened from a Tab button returns focus to it; Combobox inside a <form> — Enter when open must not submit; Combobox controlled parent that ignores onChange keeps showing the old label after Escape/blur; Tabs inside StrictMode (double effects) still register each tab once; Tab with value "" or duplicate values; removing the currently selected tab.

TRIGGERED CHECKS:
## Shared state

- **Trigger:** the change reads and then writes state kept between calls: a module-level or
  class-level dict, list, set or counter, a cache, a store, a balance, a token table, a file.
- **Check:** run the operation from 8 or more threads at once, for many rounds, on the same
  key, and check the invariant after each round (used once, never over the cap, one record per
  key). If the race window is too narrow to hit, widen it in a scratch copy with a short sleep
  between the check and the write, and say you did. A race the widened copy reproduces is
  [blocking]. The fix is a lock (or equivalent) held across both the check and the write. The
  diff needs a concurrent test of its own; if it has none, that is [blocking] too.
- **From:** token redemption and partial refunds, where every hidden test and audit passed and
  the race shipped.

## Invariants, round trips and equivalence

- **Trigger:** the criteria state something that must always hold (a balance never negative,
  a total never over a cap), a round trip (parse then format, encode then decode), idempotency
  (doing it twice equals doing it once), or that new code must match old code.
- **Check:** a property test. Use the repo's property library if it has one (Hypothesis,
  fast-check, proptest); otherwise a seeded random loop of at least 1000 generated inputs,
  including the hostile ones, that asserts the property and prints the first failing input.
- **From:** edge cases that the implementor's own tests missed because the tests shared the
  code's assumptions.

## Nesting and composition

- **Trigger:** the code walks a tree or a container (DOM, shadow roots, portals, slots,
  routers, nested config), or the thing it builds can contain another of itself.
- **Check:** nest it. Put a target inside another target, including inside another target's
  shadow root; a dialog in a dialog; a router mounted in a router. Check the inner and the
  outer each still behave as they do alone, and that nothing inside a target gets the
  treatment meant for what's outside it.
- **From:** hide-everything-else logic that walked into a nested target's shadow root, and
  dialogs where one Escape closed both.

## Focus and keyboard

- **Trigger:** the change moves, traps or restores focus, or handles keys (modals, menus,
  tabs, comboboxes, roving tab index).
- **Check:** drive the real component with user events, not function calls. Open it from a
  button and close it: focus goes back to that button, even when a child uses autoFocus. With
  a trap open, Tab and Shift+Tab never reach hidden, inert, disabled or `tabIndex=-1` content,
  including the component's own hidden panels. Escape closes only the top layer. Elements
  added after it opened are handled.
- **From:** focus traps that leaked into hidden content, and focus returned to the wrong
  element.

## Active and selected items in a changing list

- **Trigger:** the component tracks an active, highlighted or selected item in a list that
  can change while it's shown (filtered, async, reordered, prepended).
- **Check:** change the list while it's open: prepend an item, filter, remove the active one.
  The active item must still be the same item, not the same index, and Enter must commit that
  item. Clearing the selection must work (null or empty), and say so in the change event.
- **From:** comboboxes that tracked the active option by index and committed the wrong one.
